PhyNetPy Advanced Phylogenetic Network Analysis

A production Python library for constructing, simulating, comparing, and inferring phylogenetic networks. I am its technical lead and principal architect, owning architecture, compiled kernels, GPU paths, CI/CD, and releases. This page documents how it is built and how fast it actually is.

Architecture

Core Modules

The 0.6.0 public API, organized around three composable axes — your data, a biological model, and a statistical criterion — driven by three verbs.

API

infer

The public facade. Three verbs cover the whole surface: infer, score, and simulate.

  • Registry-based engine dispatch
  • Published validity matrix rejects invalid data/model/criterion combinations up front
  • Typed InferenceResult with score, trace, and posterior
DAT

data

The data axis: what you actually observed.

  • GeneTrees, Alignment, BiallelicMarkers
  • Single from_file entry point per type
  • Validation and aggregate reporting on load
MOD

models

The biological model axis, with units made explicit.

  • MSC (multispecies network coalescent), Allopolyploid
  • BranchLengthUnit — coalescent vs. substitutions per site, never guessed
  • Population-specific theta values
CRI

criteria

The statistical criterion axis: how a candidate network is judged.

  • Likelihood, PseudoLikelihood, MDC, Bayesian
  • Criterion-specific search settings carried on the object
  • Bayesian criterion wraps any objective
NET

Network

Core network data structures, backed by a compiled adjacency layer.

  • Network, MUL, Node, Edge
  • Cython NodeSet/EdgeSet give O(1) in/out-edge lookup
  • Traversal, topological order, isomorphism, subnetwork extraction
CY

cython

Four compiled extension modules carrying the hot paths.

  • graph_core_cy — adjacency maps
  • mpl_engine_cy — pseudo-likelihood triplet DP
  • gt_msc_cy, seq_engine_cy — coalescent and sequence kernels
I/O

IO

Readers and writers for every standard format in the domain.

  • NEXUS, Newick, FASTA, VCF — read and write
  • Newick dialect auto-detection and conversion
  • Structured validation summaries instead of silent failures
GTR

GTR

Time-reversible substitution models with corrected parameterizations.

  • JC, K80, F81, K81, HKY, TN93, SYM, GTR
  • Closed-form transition matrices where they exist
  • Cached eigendecomposition everywhere else
UTL

GraphUtils

Topology analysis and a full suite of network distance metrics.

  • μ-distance, hardwired/softwired cluster, tripartition, Robinson-Foulds
  • Reticulation-aware comparison with precision/recall
  • Blobs, tree-of-blobs, displayed trees, level computation
SRC

Search

Network-space search framework with pluggable move kernels.

  • Hill climbing and simulated annealing drivers
  • Reticulation add/remove/relocate, SPR, node height, inheritance probability
  • Parallel MCMC chains with Gelman-Rubin monitoring
SIM

Simulation

Ground-truth generators for benchmarking and validation.

  • Yule and constant birth-death (CBDP) network models
  • Gene trees, sequence alignments, and biallelic markers under the MSNC
  • Seeded and reproducible; true network attached to output
POP

Population Genetics

Analysis helpers for population-scale data.

  • PopulationData — never treats missing genotypes as reference alleles
  • AdmixtureGraph — validates pulse admixture semantics
  • GPU-accelerated marker likelihood via CuPy

Performance

Measured Benchmark Results

Every number on this page is produced by a reproducible harness with correctness assertions. Where PhyNetPy loses, that is reported too.

Methodology

Timings come from scripts/portfolio_benchmarks.py, portfolio_benchmarks_cython.py, and portfolio_benchmarks_kernel.py in the PhyNetPy repository. Each measurement runs a warm-up call, then reports the median of 3–5 repeats of a tight loop using time.perf_counter. Memory figures use tracemalloc and measure memory retained after construction, with builder temporaries collected, so the harness does not flatter itself by counting scratch allocations.

Critically, every optimized path is asserted against its reference implementation in the same process: the Cython pseudo-likelihood kernel is compared to the pure-Python DP (agreement: exactly 0.0), and closed-form transition matrices are compared to scipy.linalg.expm (agreement: ~1e-16). A speedup that changes the answer is a bug, not a speedup.

Raw data
The harness and its JSON output are published here so these figures can be audited or re-run.

Cython pseudo-likelihood kernel vs. pure-Python reference

Time to score one species network against its gene trees, as taxon count grows. Both paths live in the shipping library and produce bit-identical scores, so this is a clean measure of what compiling the hot loop bought. The gap widens with problem size, from 4.2× at 6 taxa to 9.2× at 24 taxa.

Transition matrices: closed forms vs. generic matrix exponentiation

0.6.0 replaced generic expm calls with closed-form solutions where the model admits one, and a cached eigendecomposition everywhere else. Result: 8.6×–19.5× faster across all eight substitution models, agreeing with SciPy to ~1e-16.

Topological accuracy vs. the incumbent implementation

μ-distance from the inferred network to the known true network across four simulated benchmark conditions (1,160 PhyNetPy runs vs. 669 PhyloNet runs). PhyNetPy is 1.8× to 4.2× more accurate depending on condition — and it solves Scenario J, which PhyloNet does not complete at all. Note that PhyNetPy's margin grows as the conditions get harder, which is the direction you want.

Efficiency

Graph Core vs. NetworkX

Identical 1,999-node / 1,998-edge topologies built in both libraries. PhyNetPy's Cython adjacency layer wins decisively on the lookups that dominate inference — and loses on generic traversal and memory. Both results are shown.

Operation PhyNetPy NetworkX Result
In-edge lookup the inference hot path 0.15 µs 1.65 µs 10.9× faster
Leaf enumeration get_leaves() 91.2 µs 349.0 µs 3.8× faster
Out-degree query 0.15 µs 0.19 µs 1.3× faster
Topological sort 1,253 µs 858 µs 1.5× slower
Retained memory 2,056 KiB 1,103 KiB 1.9× heavier
Leaf-descendant sets (all nodes) 1,132 µs — no equivalent

On the two losses. Both are deliberate trade-offs, not oversights. A PhyNetPy Node carries domain state a string-keyed NetworkX DiGraph node does not — branch lengths, inheritance probabilities, divergence times, sequence data, and reticulation flags — which costs roughly 1 KB per node and buys O(1) answers to the phylogenetic queries that run millions of times inside a search. Topological sort is slower because PhyNetPy validates acyclicity and returns rich Node objects rather than bare labels; it is also not on any hot path, so it has never been worth optimizing. Spending memory and generic-traversal speed to make the inner loop fast is the right call for this workload — but it is a trade, and worth stating plainly.

Highlights

Key Achievements

1,130 Tests in CI

1,125 passing in 34 seconds, plus memory-regression, stress, and numerical cross-check suites validated against the reference Java implementation. CI matrix spans Python 3.9–3.14 with wheel and clean-install validation gating every release.

Profile-Driven Optimization

Every speedup started with a profiler. Eliminating 3.7M redundant traversals raised search throughput 2.8× (2,742 → 972 ms/iteration); compiling the triplet DP added up to 9.2× on top of that.

Correctness Enforced by Types

Branch lengths carry explicit units, so the library refuses to guess between coalescent and substitution scales. Invalid data/model/criterion combinations are rejected up front by a published validity matrix rather than failing hours into a run.

Repeatable Releases

A one-command deploy pipeline handles version bump, test run, manifest check, build, and PyPI upload. API documentation is generated from source by a custom AST-based tool, so the docs cannot silently drift from the code.
