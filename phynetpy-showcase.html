PhyNetPy Advanced Phylogenetic Network Analysis

A Python library for constructing, simulating, comparing, and inferring phylogenetic networks. I'm its technical lead and principal architect. This page covers how it's built and how fast it actually is, with the benchmark scripts to back the numbers up.

Architecture

Core Modules

The 0.6.0 public API. Three composable axes (your data, a biological model, a statistical criterion) driven by three verbs.

API

infer

The public facade. Three verbs cover the whole surface: infer, score, and simulate.

  • Registry-based engine dispatch
  • Published validity matrix rejects invalid data/model/criterion combinations up front
  • Typed InferenceResult with score, trace, and posterior
DAT

data

The data axis: what you actually observed.

  • GeneTrees, Alignment, BiallelicMarkers
  • Single from_file entry point per type
  • Validation and aggregate reporting on load
MOD

models

The biological model axis, with units made explicit.

  • MSC (multispecies network coalescent), Allopolyploid
  • BranchLengthUnit — coalescent vs. substitutions per site, never guessed
  • Population-specific theta values
CRI

criteria

The statistical criterion axis: how a candidate network is judged.

  • Likelihood, PseudoLikelihood, MDC, Bayesian
  • Criterion-specific search settings carried on the object
  • Bayesian criterion wraps any objective
NET

Network

Core network data structures, backed by a compiled adjacency layer.

  • Network, MUL, Node, Edge
  • Cython NodeSet/EdgeSet give O(1) in/out-edge lookup
  • Traversal, topological order, isomorphism, subnetwork extraction
CY

cython

Four compiled extension modules carrying the hot paths.

  • graph_core_cy — adjacency maps
  • mpl_engine_cy — pseudo-likelihood triplet DP
  • gt_msc_cy, seq_engine_cy — coalescent and sequence kernels
I/O

IO

Readers and writers for every standard format in the domain.

  • NEXUS, Newick, FASTA, VCF — read and write
  • Newick dialect auto-detection and conversion
  • Structured validation summaries instead of silent failures
GTR

GTR

Time-reversible substitution models with corrected parameterizations.

  • JC, K80, F81, K81, HKY, TN93, SYM, GTR
  • Closed-form transition matrices where they exist
  • Cached eigendecomposition everywhere else
UTL

GraphUtils

Topology analysis and a full suite of network distance metrics.

  • μ-distance, hardwired/softwired cluster, tripartition, Robinson-Foulds
  • Reticulation-aware comparison with precision/recall
  • Blobs, tree-of-blobs, displayed trees, level computation
SRC

Search

Network-space search framework with pluggable move kernels.

  • Hill climbing and simulated annealing drivers
  • Reticulation add/remove/relocate, SPR, node height, inheritance probability
  • Parallel MCMC chains with Gelman-Rubin monitoring
SIM

Simulation

Ground-truth generators for benchmarking and validation.

  • Yule and constant birth-death (CBDP) network models
  • Gene trees, sequence alignments, and biallelic markers under the MSNC
  • Seeded and reproducible; true network attached to output
POP

Population Genetics

Analysis helpers for population-scale data.

  • PopulationData — never treats missing genotypes as reference alleles
  • AdmixtureGraph — validates pulse admixture semantics
  • GPU-accelerated marker likelihood via CuPy

Performance

Measured Benchmark Results

Every number here comes from a harness you can re-run, and every optimized path is checked against its reference implementation. The cases where PhyNetPy loses are on this page too.

Methodology

Timings come from portfolio_benchmarks.py, portfolio_benchmarks_cython.py, and portfolio_benchmarks_kernel.py in the benchmarks/ directory of this site's repository. Each measurement does a warm-up call first, then reports the median of 3–5 repeats of a tight loop timed with time.perf_counter. Memory figures use tracemalloc and measure what is still retained after construction, with builder temporaries collected, so scratch allocations don't inflate the numbers.

Every optimized path is also asserted against its reference implementation in the same process. The Cython pseudo-likelihood kernel is compared to the pure-Python DP and agrees exactly. Closed-form transition matrices are compared to scipy.linalg.expm and agree to about 1e-16. A faster kernel that returns a different number is just a bug.

Raw data
The scripts and their JSON output are here if you want to check the figures or run them yourself.

Cython pseudo-likelihood kernel vs. pure-Python reference

Time to score one species network against its gene trees as taxon count grows. Both paths ship in the library and return bit-identical scores, so this measures exactly what compiling the hot loop bought. The gap widens with problem size, from 4.2× at 6 taxa to 9.2× at 24 taxa.

Transition matrices: closed forms vs. generic matrix exponentiation

0.6.0 replaced generic expm calls with closed-form solutions where the model has one, and a cached eigendecomposition everywhere else. That works out to 8.6 to 19.5× faster across all eight substitution models, agreeing with SciPy to about 1e-16.

Topological accuracy vs. the incumbent implementation

μ-distance from the inferred network to the known true network across four simulated benchmark conditions (1,160 PhyNetPy runs against 669 PhyloNet runs). PhyNetPy comes out 1.8 to 4.2× more accurate depending on the condition, and it finishes Scenario J, which PhyloNet doesn't complete at all. The margin gets wider as the conditions get harder.

Efficiency

Graph Core vs. NetworkX

The same 1,999-node, 1,998-edge topology built in both libraries. PhyNetPy's Cython adjacency layer is much faster on the lookups that dominate inference. It's slower on generic traversal and uses more memory. Both are in the table.

Operation PhyNetPy NetworkX Result
In-edge lookup the inference hot path 0.15 µs 1.65 µs 10.9× faster
Leaf enumeration get_leaves() 91.2 µs 349.0 µs 3.8× faster
Out-degree query 0.15 µs 0.19 µs 1.3× faster
Topological sort 1,253 µs 858 µs 1.5× slower
Retained memory 2,056 KiB 1,103 KiB 1.9× heavier
Leaf-descendant sets (all nodes) 1,132 µs — no equivalent

On the two losses. A PhyNetPy Node carries state that a string-keyed NetworkX DiGraph node doesn't: branch lengths, inheritance probabilities, divergence times, sequence data, reticulation flags. That costs roughly 1 KB per node and buys O(1) answers to the phylogenetic queries a search runs millions of times. Topological sort is slower because PhyNetPy validates acyclicity and hands back Node objects instead of bare labels, and because it isn't on a hot path, so I've never had a reason to optimize it. For this workload I'd make the same trade again, but it is a trade.

Highlights

Key Achievements

1,130 Tests in CI

A 100% pass rate in 34 seconds, plus separate memory-regression, stress, and numerical cross-check suites validated against the reference Java implementation. CI runs on Python 3.9 through 3.14, and every release has to clear wheel builds and a clean-install check before it ships.

Profile-Driven Optimization

Every speedup here started in a profiler. Cutting 3.7M redundant traversals took search from 2,742 to 972 ms per iteration, a 2.8× gain, and compiling the triplet DP added up to 9.2× on top of that.

Correctness Enforced by Types

Branch lengths carry their units in the type, so the library won't guess between coalescent and substitution scales. Invalid data, model, and criterion combinations are caught at the call site rather than hours into a run, and the validity matrix is part of the public docs.

Repeatable Releases

One command handles the version bump, test run, manifest check, build, and PyPI upload. API docs are generated from source by an AST-based tool I wrote, so they can't drift away from the code without someone noticing.
