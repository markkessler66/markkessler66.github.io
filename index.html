BioForge

GPU-Accelerated Synthetic Sequence Generation

BioForge is a GPU-accelerated Python library for generating synthetic DNA, RNA, and protein sequences with known ground truth. Designed for training and benchmarking ML models in computational biology. It includes evolutionary models (substitution, indels, recombination), population genetics simulations, sequencing error models, and ML-ready outputs (one-hot encoding, PyTorch datasets) with full reproducibility through configuration tracking.

What Shipped in PhyNetPy 0.6.0

The 0.6.0 release was a ground-up API redesign paired with measured performance work

API

Typed Three-Axis API

Collapsed a sprawling command surface into one composable API: pick your data, biological model, and statistical criterion, then call infer, score, or simulate. Invalid combinations are rejected up front by a published validity matrix instead of failing deep in a run.

FAST

Compiled Hot Paths

Four Cython extension modules back the graph core and the scoring kernels. The pseudo-likelihood DP runs up to 9.2× faster than the pure-Python reference while producing bit-identical scores, and closed-form transition matrices beat scipy.linalg.expm by 8.6–19.5×.

SAFE

Correctness by Construction

Branch lengths now carry explicit units, so the library refuses to guess between coalescent and substitution scales — eliminating a class of silent scientific errors. Backed by 1,130 tests including numerical cross-checks against the reference Java implementation.

About Me

I like problems where the naive solution doesn't finish. Most of my work sits on NP-hard graph and statistical inference problems, which means the interesting engineering is in the profiling: figuring out which 5% of the code is 90% of the runtime, then deciding whether the fix is a compiled kernel, a cache, a parallel pool, or a fundamentally better algorithm. I care a lot about proving the fix worked — every optimization I ship has a benchmark and a correctness assertion behind it.

Increasingly the part I enjoy most is the leadership side: setting technical direction, designing APIs that other people can build on, making releases boring and repeatable, and bringing collaborators up to speed on a dense codebase. I'm looking for a senior role where I can keep doing that at a larger scale.

When I'm not coding, you can find me gardening, cooking, playing tennis/guitar/golf, or going on a walk with my lovely fiancée. I believe in open-source collaboration and am always excited to connect with fellow engineers and researchers.
