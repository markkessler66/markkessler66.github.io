BioForge

GPU-Accelerated Synthetic Sequence Generation

A GPU-accelerated Python library that generates synthetic DNA, RNA, and protein sequences with known ground truth, so you can train and benchmark ML models against data where you already know the right answer. It covers substitution, indel, and recombination models, population genetics simulation, and sequencing error, and it writes out one-hot arrays and PyTorch datasets directly. Every run records its config so the data can be regenerated.

What Shipped in PhyNetPy 0.6.0

0.6.0 was a full API redesign plus a round of performance work I could actually measure

API

Typed Three-Axis API

The old command surface had grown in every direction, so I replaced it with one composable API. You pick your data, a biological model, and a statistical criterion, then call infer, score, or simulate. Combinations that don't make sense get rejected at the call site rather than two hours into a run, and the validity matrix is published so you know which ones those are.

FAST

Compiled Hot Paths

Four Cython extension modules sit under the graph core and the scoring kernels. The pseudo-likelihood DP runs up to 9.2× faster than the pure-Python version and returns bit-identical scores. Closed-form transition matrices beat scipy.linalg.expm by 8.6 to 19.5×.

SAFE

Hard to Misuse

Branch lengths now carry their units in the type, so the library won't quietly guess between coalescent and substitution scales. That mistake used to produce wrong results without raising anything. There are 1,130 tests behind it, including numerical cross-checks against the reference Java implementation.

About Me

I like problems where the obvious solution doesn't finish running. Most of my work is on NP-hard graph and inference problems, so the interesting part is usually the profiling: finding the 5% of the code that accounts for 90% of the runtime, then working out whether the fix is a compiled kernel, a cache, or a better algorithm. I try not to claim a speedup I haven't measured, which is why the numbers on this site ship with the scripts that produced them.

These days the work I enjoy most is the part that isn't writing code: picking a direction, designing an API other people have to live with, making releases boring, getting a new contributor productive in a dense codebase. I'm looking for a senior or lead role where I can do more of that.
